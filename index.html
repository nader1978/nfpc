🔁 6 · Outstanding rounds — what could not be collected is kept and served in the next round
How it works. Round 1: the picking list is made from the stock available now. Press Save this round — what could not be collected is stored in the SharePoint outstanding orders list (one row per order date, route and item). When the factory stock arrives, load the stock again, press Load outstanding balance and plan: the outstanding rows become the demand (served before new orders) and the same SharePoint rows are updated, never duplicated. Repeat until the order is fulfilled, or tick Close on rows that will never be available and move them to the unavailable stock list. Tip: when you start a later round, untick or remove the DSO files that were already served.

🔐 Login control — SharePoint user list ADMIN ONLY
Each user is checked against a SharePoint list every time the system opens and every 5 minutes. 🌐 Global Connection Settings ADMIN ONLY
These values are shared by all users. Only administrators can view or change them.
📁 Shared token file — publish once, every user picks it up automatically
Admin: save the Site URL + token above, press Export token file and put the file (sp_token.json) in a shared location — e.g. the same SharePoint library / folder as this HTML. Users then get the token without asking: the app reads the file on start and every 10 minutes. Re-export when the token expires. Anyone who can read the file can use the token — restrict the folder to your team.
🔐 Microsoft sign-in — no pasted token; each user signs in with their own account
Register the app once in Microsoft Entra (Azure AD) → App registrations → New → Single-page application redirect URI = the address this page is opened from (https:// or http://localhost). API permissions: Microsoft Graph Sites.ReadWrite.All + User.Read (and SharePoint AllSites.Write for attachments), then grant admin consent. Paste the two IDs below, or fill MS_AUTH_DEFAULT in the file so every user gets them.

📨 Send email directly — adds a “🚀 Send now” button to every Share-by-email window
A web page cannot log in to a POP3/SMTP mail server, so choose one of these two ways. Microsoft 365: the mail is sent from the signed-in user's own mailbox through Microsoft Graph — no password is stored. One-time admin step: Entra → App registrations → your app → API permissions → Add → Microsoft Graph → Delegated → Mail.Send, then grant admin consent (needs the Microsoft sign-in above, opened from https:// or http://localhost). Power Automate: create a flow “When an HTTP request is received” → “Send an email (V2)”, paste its POST URL here. Anyone who has the URL can send mail through the flow, so keep the file inside your organisation.
Power Automate flow set-up (copy/paste)
1) When an HTTP request is received → Request Body JSON Schema:
{"type":"object","properties":{"to":{"type":"string"},"cc":{"type":"string"},"subject":{"type":"string"},"bodyHtml":{"type":"string"},"sender":{"type":"string"},"attachments":{"type":"array","items":{"type":"object","properties":{"name":{"type":"string"},"contentType":{"type":"string"},"contentBase64":{"type":"string"}}}}}}
2) Send an email (V2): To = to, CC = cc, Subject = subject, Body = bodyHtml (switch the editor to code view </>), Attachments → switch to array input and use attachments with Name = name, Content = base64ToBinary(item()?['contentBase64']).
3) Save, copy the generated HTTP POST URL into the box above. Sent as: the flow owner (or use “Send an email from a shared mailbox”).

📦 Warehouse — Batch Allocation (FEFO)

Load the order file, optionally group it, map the fields (file ↔ batch list), then click 🔍 Lookup Batch (FEFO) to allocate quantities against the batch list using First-Expired-First-Out. Results can be printed, exported, or uploaded.

⚙ Field Mapping

Map the file's SKU, UOM, and Qty Requested columns, and the batch list's SKU, UOM, Qty Balance, Batch Code, Prod Date, and Expiry Date columns. Auto-Detect tries to guess; override any field manually. Mapping is saved per batch list, per user.
